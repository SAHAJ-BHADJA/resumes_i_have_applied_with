## In each coding round — the script

**0–3 min · Clarify.** Restate the problem in your own words. Ask about input size, duplicates, negatives, empty input, sorted, in-place, return index or value. **Ask about expected scale** — it signals Customer Obsession.

**3–6 min · Examples.** Write one small example and its expected output, plus one edge case. *This is the step that unfreezes you.* Don't skip it under time pressure.

**6–10 min · Brute force, out loud.** State it. State its complexity. **Do not code it.**

**10–14 min · Optimise, then get buy-in.** Name the pattern. Then say the highest-value sentence available to you:

> **"Does that approach sound reasonable before I start coding?"**

It prevents 20 wasted minutes and reads as Earn Trust.

**14–32 min · Code.** Write the **function signature first**, then the return statement, then fill the middle. Blank-page paralysis dies once a skeleton exists. Narrate continuously.

**32–38 min · Dry run.** Walk your code line by line, out loud, tracking variable values against your small example.
> **This is your superpower.** You said you can explain any code by looking at it. This is exactly that skill, and it catches most bugs. It also reads as Dive Deep.

**38–42 min · Complexity and edge cases.** Time and space, stated confidently. Then name three edge cases and check one.

**42–45 min · Offer improvements.** *"If the input were streaming instead, I'd..."* — Think Big signal.

---

## If you're running out of time

**Working brute force beats buggy optimal.** Amazon interviewers value correct code over clever code. Get something correct, then say:

> *"This is O(n²). The O(n) version uses a hashmap — I can code that next if we have time."*

That scores well. A half-finished optimal solution that doesn't run scores badly.

---

## If you get stuck

- **Say so, out loud, with what you've ruled out.** *"I've ruled out a plain sliding window because of the negatives — I'm thinking about prefix sums."* Interviewers actively give hints, and **how you take a hint is itself scored.**
- Silence is the worst option available. A wrong idea spoken beats a right idea unspoken.

---

## Between rounds

- **Do not replay the previous round.** Each interviewer scores independently and does not see the others' feedback until the debrief. A bad Round 1 is fully recoverable — the debrief weighs the whole picture.
- Drink water. Eat the snack. Reset.

---

## Every round has an LP component

Every interviewer is assigned 2–3 Leadership Principles and must return concrete evidence. Expect behavioural questions inside technical rounds — for many candidates they consume more than half the hour.

- **Say "I," not "we."** The interviewer cannot score "we."
- **Every story ends in a number and an outcome.**
- **Keep them under 2.5 minutes.** Let them ask follow-ups; that's a good sign.

---

## Questions for them — have 2 per interviewer

- *"What does on-call look like for this team?"*
- *"What's the biggest piece of technical debt you're carrying right now?"*
- *"How does this team decide what to build next?"*
- *"What does the first six months look like for someone joining?"*

Walk in, clarify the problem, say your approach out loud, and write the code.
